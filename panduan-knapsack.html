Memahami Algoritma Knapsack Problem

Pelajari rahasia di balik sistem optimasi portofolio investasi kita. Knapsack Problem adalah algoritma optimasi matematis yang mencari kombinasi item terbaik untuk mendapatkan keuntungan maksimal tanpa melebihi batas kapasitas.

Pengantar Analogi

Apa Itu Knapsack Problem?

"Knapsack" dalam bahasa Inggris berarti ransel. Bayangkan seorang pendaki (atau pencuri) yang memiliki sebuah ransel dengan kapasitas berat maksimal tertentu. Ia dihadapkan pada kumpulan barang, di mana masing-masing barang memiliki berat (weight) dan nilai (value).

Pertanyaannya: Barang mana saja yang harus dimasukkan ke dalam ransel agar mendapatkan total nilai tertinggi, tanpa membuat ransel robek (melebihi kapasitas)?

Kapasitas (W)

Batas maksimal beban yang bisa ditampung.

Berat (w)

Cost/biaya/berat dari setiap item.

Nilai (v)

Keuntungan/profit dari setiap item.

Varian Algoritma

0/1 Knapsack vs Fractional Knapsack

Ada dua variasi utama dari problem ini. Simulator kita menggunakan 0/1 Knapsack karena kita tidak bisa membeli "setengah" dari produk investasi (harus bulat).

0/1 Knapsack Problem

Aturannya ketat: Anda mengambil seluruh bagian dari sebuah barang, atau tidak mengambilnya sama sekali (0 atau 1). Barang tidak bisa dipotong atau dipecah.

  • Pendekatan: Dynamic Programming (DP).
  • Keakuratan: Sangat akurat (Pasti menemukan nilai mutlak maksimal).
  • Kondisi: Cocok untuk barang diskrit (TV, Kulkas, Produk Reksa Dana).
%

Fractional Knapsack

Anda diizinkan untuk mengambil sebagian atau memotong barang tersebut untuk memenuhi sisa kapasitas ransel.

  • Pendekatan: Algoritma Greedy (mengurutkan rasio value/weight).
  • Kecepatan: Sangat cepat.
  • Kondisi: Cocok untuk barang cair/bubuk (Beras, Tepung, Emas).

Logika Matriks Dynamic Programming (2D)

Untuk memecahkan 0/1 Knapsack, kita membuat tabel dua dimensi (matriks). Baris merepresentasikan barang yang tersedia (i), dan kolom merepresentasikan kapasitas ransel dari 0 hingga kapasitas maksimum (w).

Formula Utama (The Bellman Equation)
dp[i][w] = Math.max( dp[i-1][w], dp[i-1][w-w_i] + v_i )

Penjelasan:

  • dp[i-1][w] = Jangan ambil barang ke-i. Ambil profit sebelumnya.
  • dp[i-1][w-w_i] + v_i = Ambil barang ke-i. Kosongkan ruang sebesar berat barang (w_i), lalu tambahkan profit barang ini (v_i).
  • Fungsi Math.max() akan memilih langkah mana yang memberikan profit lebih besar.
Item (i) Kapasitas Tersedia (w)
0 1 2 3 4 5
0 (Kosong) 0 0 0 0 0 0
1 (w=2, v=3) 0 0 3 3 3 3
2 (w=3, v=4) 0 0 3 4 4 7
3 (w=4, v=5) 0 0 3 4 5 7

Contoh pengisian matriks DP sederhana (Bottom-Up Approach). Angka di dalam kotak adalah nilai (profit) maksimal yang dicapai.

Mengatasi Limitasi Memori

Mengapa Kita Butuh GCD Scaling?

Pada kode simulator RDPU kita, terdapat sebuah fungsi khusus bernama gcdArray(). Mengapa ini penting?

Kompleksitas memori dari DP 0/1 Knapsack adalah O(N * W) di mana N adalah jumlah barang dan W adalah kapasitas. Dalam dunia investasi, kapasitas (W) bisa mencapai puluhan juta rupiah (contoh: Rp 10.000.000). Membuat array 2D berukuran (10 * 10.000.000) di JavaScript akan menyebabkan browser Crash / Out of Memory.

Solusi Pintar:

Karena minimum pembelian (weight) dan modal (capacity) reksa dana biasanya berkelipatan puluhan ribu (misal: Rp 10.000, Rp 50.000), kita mencari Faktor Persekutuan Terbesar (FPB / GCD) dari semua angka tersebut. Jika GCD-nya adalah 10.000, maka modal Rp 10.000.000 diskala menjadi hanya 1.000. Matriks DP mengecil secara drastis dari 10.000.000 kolom menjadi hanya 1.000 kolom tanpa kehilangan akurasi matematika!

FAQ Seputar Algoritma

Pendekatan "Greedy" (langsung memilih return persentase tertinggi) seringkali gagal karena masalah batas "Minimum Pembelian". Misalnya, produk A punya return 8% tapi min buy-nya Rp 5.000.000. Jika modal Anda Rp 6.000.000, Anda terpaksa menyisakan Rp 1.000.000 menganggur (idle money). Knapsack DP akan melihat kombinasi menyeluruh: mungkin lebih baik membeli Produk B (min buy Rp 3jt, return 6%) dan Produk C (min buy Rp 3jt, return 5%), sehingga modal habis terpakai dan total profit dalam Rupiah jauh lebih besar.

Algoritma ini menjamin penemuan kombinasi optimal (profit maksimal) berdasarkan "Data Historis" (Return 1 Tahun ke belakang) yang dimasukkan. Namun, algoritma ini tidak bisa memprediksi pergerakan pasar di masa depan. Imbal hasil di masa lalu tidak menjamin kinerja masa depan. Algoritma ini murni mengoptimalkan kerangka matematisnya.

Script simulator saat ini menggunakan murni 0/1 Knapsack, artinya setiap produk reksa dana di daftar CSV hanya bisa dipilih maksimal 1 kali. Jika Anda ingin mengizinkan pembelian produk yang sama berulang kali (selama modal cukup), algoritmanya harus diubah menjadi Unbounded Knapsack Problem.
